## 二、项目概况（可直接放进报告）

### 2.1 项目简介

项目名称为 **MiCode Notes（小米便签）**，上游仓库为 <https://github.com/MiCode/Notes>。它是一个传统 Android 原生便签应用，主要功能包括便签与文件夹管理、搜索、提醒、桌面小组件、文本导出，以及基于 Google Task 的同步。

本次分析基于上游 `master` 分支，读取时对应提交 `81a66024fe48eaa2206b854430856fe3875ff3ba`。仓库共识别到 147 个文件，其中 Java 文件 39 个、XML 文件 38 个；Java 源文件按顶层功能包统计如下：

| 功能包 | Java 文件数 | 主要职责 |
|---|---:|---|
| `data` | 4 | 数据表常量、SQLite 数据库、ContentProvider、联系人数据访问 |
| `gtask` | 12 | Google Task 本地模型、远端通信和同步服务 |
| `model` | 2 | 便签编辑过程中的领域模型和数据装载 |
| `tool` | 4 | 数据操作、备份导出、资源解析、启动辅助 |
| `ui` | 14 | 列表、编辑、搜索、设置、适配器和自定义视图 |
| `widget` | 3 | 2×2、4×4 桌面小组件及服务 |

说明：上述是“文件数”，不是代码行数。正式质量报告中应在统一拉取源码后使用 `cloc src` 或同类工具补充有效代码行、注释行和空行数据，避免把字节数误写成代码行数。

### 2.2 技术与运行特点

- 使用 Java 与 Android XML；
- 使用 Eclipse/ADT 年代的 Android 工程结构，没有现代 Gradle Wrapper；
- 核心数据保存在 SQLite 中，并通过 `NotesProvider` 统一访问；
- 列表查询与数据库操作使用 `ContentResolver`、`AsyncQueryHandler`；
- 同步模块依赖早期 Google Task 接口，现代环境下很可能需要替换或降级处理；
- 代码历史较早，现代 Android SDK 上的构建兼容、安全权限和 API 弃用问题，是质量分析的重要内容。

### 2.3 原始架构说明

系统可按“界面层—模型层—数据层—基础设施层”理解：

1. `ui` 接收用户操作并展示便签、文件夹、搜索和设置界面；
2. `model` 封装编辑中的便签状态，并通过数据接口保存；
3. `data` 以 `NotesProvider` 为统一入口，底层由 `NotesDatabaseHelper` 管理 SQLite；
4. `tool` 提供批量移动/删除、备份导出与资源解析；
5. `widget` 复用数据和模型能力，将便签展示在桌面；
6. `gtask` 负责本地便签与远端任务之间的转换、比较和同步。

原始架构图见 `原始架构包图.puml`，用例图见 `用例图.puml`。

## 三、组长维护项：便签置顶/取消置顶

### 3.1 需求描述

用户可以在便签列表中长按一条或多条便签，选择“置顶”；置顶便签保持在普通便签之前。再次选择“取消置顶”后，便签恢复按最后修改时间排序。带提醒的置顶便签优先显示时钟图标，普通置顶便签显示星标，从而避免提醒信息被覆盖。

### 3.2 验收标准

- 支持单条和批量置顶；
- 支持取消置顶；
- 文件夹仍排在便签前面，不改变原有列表分组；
- 同一组内置顶便签在前，置顶状态相同时按修改时间倒序；
- 应用重启后置顶状态仍保留；
- 数据库从版本 4 升级到版本 5 时，旧便签内容不丢失，旧数据默认不置顶；
- 没有提醒的置顶便签显示星标，带提醒的便签仍显示时钟。

### 3.3 设计方案

本维护项涉及 7 个源码/资源文件和 3 个本地化资源文件：

| 文件 | 修改内容 |
|---|---|
| `Notes.java` | 在 `NoteColumns` 中新增 `pinned` 字段常量 |
| `NotesDatabaseHelper.java` | 数据库版本 4→5；建表和升级迁移增加 `pinned` 列 |
| `NoteItemData.java` | 查询投影中读取置顶状态，并提供 `isPinned()` |
| `NotesListActivity.java` | 增加置顶操作、批量更新，并把列表排序改为 `TYPE DESC, PINNED DESC, MODIFIED_DATE DESC` |
| `NotesListItem.java` | 对无提醒的置顶便签显示星标 |
| `note_list_options.xml` | 多选操作栏增加“置顶/取消置顶”入口 |
| 3 份 `strings.xml` | 增加英文、简体中文、繁体中文文案 |

详细关系见 `置顶功能设计类图.puml`，实现内容见 `便签置顶功能.patch`。

### 3.4 代码标注要点（可放进“详细阅读/标注”章节）

1. `Notes.NoteColumns` 是便签表字段的统一契约；新增字段必须同时进入建表 SQL 和升级 SQL。
2. `NoteItemData.PROJECTION` 的列顺序与下方索引常量严格对应。为避免破坏原有索引，本次把 `PINNED` 追加到投影末尾，索引设为 12。
3. `NotesListActivity.startAsyncNotesListQuery()` 决定列表排序，先按类型排序可保留系统文件夹/普通文件夹的原有位置，再按置顶和修改时间排序。
4. 批量操作使用参数化占位符构造 `_id IN (?,...)`，不把 ID 直接拼进 SQL，便于复核并保持查询写法规范。
5. `NotesListItem.bind()` 中提醒图标优先级高于置顶星标，避免置顶功能遮蔽原有提醒语义。

## 五、质量分析开头（可直接放进质量报告）

### 5.1 初步优点

- 包结构按界面、模型、数据、工具、同步和小组件划分，职责总体清楚；
- 数据访问集中在 ContentProvider，界面层没有直接操作 SQLite；
- 对批量移动、删除、小组件更新等业务已做一定封装；
- 源码规模适中，适合课堂开展全局泛读和重点类详读。

### 5.2 初步风险

| 风险 | 影响 | 建议检查方式 |
|---|---|---|
| 工程年代久、无 Gradle Wrapper | 新版 Android Studio 不能直接稳定构建 | 记录导入过程、SDK/JDK 版本与全部兼容修改 |
| 早期 Google Task 同步接口 | 登录或网络同步可能不可用 | 将同步独立列为兼容性风险，不承诺无证据的可用性 |
| 旧 API 与旧权限模型 | 新 Android 系统可能编译警告、运行失败 | lint、编译日志、目标版本设备实测 |
| 数据库升级链 | 跨版本升级可能丢数据或崩溃 | 构造旧数据库执行升级测试 |
| 关键逻辑缺少自动化测试 | 回归风险较高 | 优先覆盖数据工具类、数据库迁移和新增功能 |
| UI 类职责较多 | 可维护性和测试性下降 | 用类复杂度、方法长度和依赖关系做量化说明 |

注意：正式报告中的 SonarQube、Android Lint、测试覆盖率、复杂度和缺陷数量必须来自实际工具结果，不能用估计值代替。

## 六、仓库与协作规范

建议仓库结构：

```text
MiCode-Notes-Team/
├─ src/、res/、AndroidManifest.xml ...  # 原项目及维护后的源码
├─ doc/
│  ├─ reading/                          # 模块阅读与代码标注
│  ├─ quality/                          # 质量工具结果与分析
│  ├─ maintenance/                      # 每项维护设计、截图、测试
│  └─ meeting/                          # 周会/讨论记录
└─ report/                              # 两份报告与 PPT
```

分支约定：

- `master`：先保存未经修改的原始代码基线；
- `develop`：小组集成与阶段验收；
- `member/leader-pin`：组长置顶功能；
- `member/a-word-count`：组员 A 字数统计；
- `member/b-quick-reminder`：组员 B 快捷提醒；
- `member/c-build-quality`：组员 C 构建兼容、质量检查与缺陷修复。

提交信息建议采用：`模块: 动词 + 内容`，例如：

```text
data: add pinned column and v5 migration
ui: support batch pin and unpin actions
doc: add pin feature design and test evidence
```

每项维护合入 `develop` 前必须同时具备：需求说明、设计说明、代码提交、测试用例、执行结果、关键截图和提交 SHA。

# 可直接发到小组群的任务通知

大家好，我们这次选的项目是 MiCode Notes：<https://github.com/MiCode/Notes>。作业最终要交两份报告（源码泛读/标注/维护报告、质量分析报告）、维护后的仓库、测试与质量检查证据、汇报 PPT。我们四个人每人负责一个模块和一项维护，最后由我统一集成。

统一规则：原始代码先放 `master`，集成放 `develop`，每个人只在自己的分支开发；不要直接改 `master`。每个人的成果都要包括“模块阅读说明 + 关键代码标注 + 维护设计 + 代码提交 + 测试用例与结果 + 运行截图 + commit SHA”，不能只交代码。遇到工程太老编译不了，也要把环境、完整报错、尝试过程和解决办法记录下来。

第一阶段请先完成：拉取项目、建立个人分支、列出自己模块的类与职责、选 2～3 个关键类做详细阅读和标注、记录至少 1 个质量问题。完成后在群里发分支名、阅读文档位置和第一次提交 SHA。

具体分工如下：

**组员 A：UI/资源模块 + 编辑页实时字数统计**

- 分支：`member/a-word-count`
- 阅读范围：`src/net/micode/notes/ui/`、`res/layout/`、`res/menu/`、`res/values*/`。
- 重点类：`NoteEditActivity`、`NotesListActivity`、`NotesListAdapter`、`NotesListItem`。
- 维护任务：在便签编辑页增加实时字数统计，输入、删除、切换清单模式后数字要同步更新；补充中英文资源，界面不能遮挡原有按钮。
- 至少测试：空便签、中文、英文、数字/符号、换行、长文本、横竖屏或重进页面后的显示。
- 文档要写：页面流程、关键 UI 关系、改动前后截图、测试表、修改文件清单。

**组员 B：提醒/小组件/工具模块 + 快捷提醒**

- 分支：`member/b-quick-reminder`
- 阅读范围：`src/net/micode/notes/widget/`、`src/net/micode/notes/tool/`，以及 `ui` 中设置提醒的相关代码。
- 重点类：小组件 Provider/Service、`DataUtils`、`ResourceParser`、提醒时间选择相关类。
- 维护任务：在原有提醒时间设置中增加快捷选项，例如“今天晚些时候”“明天上午 9:00”“一周后”；仍保留原有自定义时间。
- 至少测试：跨天、月末、年末、已过时间、取消提醒、应用重启、提醒触发；同时检查小组件显示是否受影响。
- 文档要写：提醒流程图、关键类说明、边界条件、改动前后截图、测试表、修改文件清单。

**组员 C：同步/质量与构建模块 + 兼容修复**

- 分支：`member/c-build-quality`
- 阅读范围：`src/net/micode/notes/gtask/`、`AndroidManifest.xml`、工程配置文件，并负责汇总质量工具结果。
- 重点类：`GTaskSyncService`、本地/远端节点模型、同步任务类，以及构建入口。
- 维护任务：先让项目在我们统一的 Android Studio/JDK/SDK 环境中可重复构建；从实际构建、lint 或运行日志中选择一个可复现问题修复。Google Task 接口若已经失效，不要硬写“同步可用”，要把它作为兼容性风险分析。
- 质量任务：统计 Java/XML 文件和代码行，运行可行的 lint/SonarQube 或替代静态检查，整理缺陷、坏味道、复杂度和安全告警；记录工具版本和命令。
- 至少测试：干净环境构建、安装启动、核心页面冒烟测试、修复前复现与修复后验证。
- 文档要写：构建环境表、问题复现步骤、错误日志、修复说明、质量数据表、测试证据、修改文件清单。

我的任务是数据/模型/总体架构与集成，维护项为“便签置顶/取消置顶”。我会提供数据库迁移、列表排序、批量置顶、星标显示、设计图和测试用例，并负责合并 `develop`、解决冲突、统一报告和 PPT。

第二阶段提交时，每个人在群里按这个格式发：

```text
姓名：
分支：
完成内容：
关键提交 SHA：
测试通过/失败项：
文档与截图路径：
需要协助的问题：
```

任何人准备合并前先从 `develop` 更新并自行解决个人分支冲突，然后发合并请求给我检查。没有测试记录、截图或说明的提交先不合入。
